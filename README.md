# 存储周期温度计 v3

DRAM/NAND 周期监测。每周一北京时间 08:30 自动运行：Claude 联网**只提取原始指标**，
分数由 `scripts/scoring.py` 机械映射，上传微信云开发 Storage，小程序读取展示。

## v3 与旧版的根本区别

旧版让模型直接打分（0–100 自由裁量）；v3 让模型只填 `wow_pct`、`yoy_pct`、
`inventory_weeks` 等可核对的数值，**打分完全由代码完成**。同一周的实测差异：
旧口径 58 分，新口径 32 分——旧版把 TrendForce 的谨慎措辞（"成交清淡""买方抵制"）
读成了看跌，而同期现货价两周涨了 10.6%、连创新高。

## 输出的四个维度

| 维度 | 含义 |
|---|---|
| 顶部温度 | 距周期顶部的接近程度（加权，慢变量已衰减） |
| 底部温度 | 距周期底部的接近程度（用变化率构造，≥60 为底部区间） |
| 主触发器 | ①≥38 且 ②≥55 且 ④≥35，回测两轮各提前 2 季度、零误报 |
| 市场定价锚 | DRAM ETF 距高点回撤，独立告警不入分 |

相位状态机（扩张/顶部预警/下行/筑底）确保同样的高分在过顶后含义反转。

## 数据分层（重要）

- `quarterly`：2018Q1–2026Q3 共 35 期，**季度规则重建，非实测**。周度历史数据在付费墙后，
  不做即为不编。置信度逐期标注。
- `weekly`：2026-07 起，**真实现货价实测**，来源 TrendForce 周报（免费公开部分）。

两条序列口径相同、数据性质不同，小程序分 tab 展示，不合成一条曲线。

## 部署

Secrets：`ANTHROPIC_API_KEY`、`TCB_SECRET_ID`、`TCB_SECRET_KEY`、`TCB_ENV`。
可选 Variables：`ANTHROPIC_BASE_URL`（默认中转网关）、`CLAUDE_MODEL`、`CLAUDE_MAX_TOKENS`。
小程序端只需在 `config.js` 填 `dataUrl`，并把该域名加入 request 合法域名。

## 口径一致性保障

1. 打分规则集中在 `scoring.py`，实时与回测**共用同一份代码**，不可能出现两套口径。
2. workflow 每次运行后自动跑 `backtest/probe.py` 回归自检，规则被改动导致历史结论变化会立刻暴露。
3. 季度类指标带 `asof` 发布日，未更新则沿用上期数值，杜绝无信息期的虚假微调。
4. `history_v3.json` 随 git 提交，每期读数的指标、来源、置信度可追溯。
